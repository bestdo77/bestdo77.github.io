01 — About

About me

I'm a Computer Science student at Tianjin University, and I mostly work on infrastructure — the storage and systems that sit underneath machine learning.

Right now I'm at ByteDance, working on the Parameter Server — the high-throughput, low-latency store behind the AML machine-learning platform. Before that, competitive programming (I'm an ICPC silver medalist) gave me most of my data-structure and performance habits.

I like working across the whole stack, from low-level code up to the models on top. One project on astronomical light-curve classification grew into a first-author paper accepted by ApJS. Outside of systems, I'm into astronomy.

03 — Projects

Selected projects

Parallel Model Eviction for a Large-scale Parameter Server

ByteDance · Infra
2026 · C++ · Parameter Server · AOF + SSD tiered storage
  • Ordered concurrency: introduced per-region coordinators that keep the append-only log and the SSD write path strictly ordered while eviction runs across many threads.
  • ~35% faster: parallelized the eviction hot path (single-thread falls back to the original code path as a safety net) — end-to-end eviction on a large production model sped up roughly 35% with near-flat memory and virtually no extra disk I/O.
  • Correctness first: verified by bit-exact, per-FID comparison of dump files across single-threaded, multi-threaded and concurrent-model runs — zero mismatches against the original path.

1%extra memory
~0%extra disk I/O

Incremental Management & Real-time Classification of Large-scale Astronomical Light Curves

Lead · Accepted by ApJS
2025.03 — 2026.06 · TDengine · LightGBM · ONNX · C++ · Python
  • High-performance storage: designed a one-table-per-source model with HEALPix spatial indexing on TDengine — 48M rows ingested in 33s, millisecond cone searches (full scan 15s → 50ms).
  • Lightweight inference: replaced a 21.8GB random forest with LightGBM exported to ONNX — 87× smaller (252MB), memory from 22GB to <10MB, 93.6% accuracy with no GPU.
  • Incremental triggering: confidence filtering re-classifies sources as new data arrives; high-confidence results emit at 50% curve completeness to trigger follow-up.
